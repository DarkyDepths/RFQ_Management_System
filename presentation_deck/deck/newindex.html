High-level system shape — three layers: entry (UI), RBAC (Role-Based Access Control via rfq_iam_ms, future seam), and three peer backend services. rfq_manager_ms owns operational lifecycle truth and is the backbone (visually emphasized so the role is felt). rfq_intelligence_ms = structured evidence around workbooks and MR packages. rfq_copilot_ms = bounded conversation with safe answers and manager context. Each backend owns its own data store; manager's two stores (Operational DB + File storage) sit directly beneath it. Azure OpenAI is consumed by intelligence + copilot — explicitly not by manager. File storage is local today; Azure Blob is the planned target. RBAC (rfq_iam_ms) is a future seam — the slide names it as the access concern but the service is not yet implemented. Don't merge it with the three peer backends — it serves a different role (authorization above the domain peers, not a peer itself).
