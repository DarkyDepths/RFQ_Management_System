# Meeting Notes and Context Warning

The files in this folder contain meeting notes, discussion summaries, stakeholder feedback, audit notes, supervisor comments, and project context.

They are useful for understanding:

- business context;
- audit narrative;
- client expectations;
- supervisor feedback;
- project timeline;
- scope changes;
- rationale behind decisions;
- evidence of the BOQ-to-lifecycle-intelligence pivot.

However, these files must not be treated as source of truth for implementation status.

## Source-of-truth rule

For implementation claims, use:

1. Current repository code and tests.
2. Latest implementation audit.
3. Latest validation evidence report.
4. Current report draft.
5. Architecture documents.
6. Meeting notes and context files.

## How to use these notes

Use them to support narrative, context, timeline, and rationale.

Do not use them to claim that a feature is implemented, validated, integrated, or production-ready unless code or validation evidence confirms it.

## Examples

- A meeting note saying “we want AI prediction” does not mean prediction is implemented.
- A stakeholder request for “automatic communication” does not mean outbound email automation is implemented.
- A supervisor comment about adding a State of the Art chapter is valid report guidance.
- Audit notes about GHI pain points are valid business-context evidence.
