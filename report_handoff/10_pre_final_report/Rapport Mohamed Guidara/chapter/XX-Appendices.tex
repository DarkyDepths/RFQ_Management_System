\section{Detailed Use Case Descriptions}
\label{app:use-cases}

This appendix expands the principal use cases introduced in Chapter~\ref{chap:requirements} (Section~\ref{sec:use_cases}) with structured descriptions covering actor, preconditions, main flow, alternate flows, and postconditions. Use cases related to target / future actors (Administrator template management, full executive analytics) are listed for completeness; current-scope implementation status is indicated per Chapter~\ref{chap:requirements}.

\subsection{UC-01, Register RFQ}
\textbf{Primary actor:} Estimation Manager. \textbf{Preconditions:} the user is authenticated; at least one workflow template is seeded in the manager service. \textbf{Main flow:} (1)~the user opens the new-RFQ form; (2)~provides metadata and selects a workflow template; (3)~the system instantiates the RFQ, allocates a unique code, and creates per-stage instances; (4)~the system persists and returns the RFQ. \textbf{Alternate flows:} (3a)~validation failure; (3b)~code-counter contention. \textbf{Postconditions:} RFQ exists with initial stage active and lifecycle timestamps recorded.

\subsection{UC-02, Advance RFQ Stage}
\textbf{Primary actor:} Estimator or Estimation Manager. \textbf{Preconditions:} the RFQ exists. \textbf{Main flow:} (1)~user submits advance request; (2)~system executes mandatory-field gate; (3)~system executes blocker gate; (4)~system executes transition-validity gate; (5)~transaction commits atomically. \textbf{Alternate flows:} Gate failures yield structured constraint exceptions. \textbf{Postconditions:} RFQ advances, or lifecycle remains unchanged upon gate failure.

\subsection{UC-03, Manage Stage Artifacts}
\textbf{Primary actor:} Department User, Estimator, or Estimation Manager. \textbf{Preconditions:} appropriate role context. \textbf{Main flow:} (1)~user attaches subtask, note, or file; (2)~system validates payload constraints; (3)~subtask updates propagate. \textbf{Alternate flows:} (1b)~edit attempt on append-only note refused. \textbf{Postconditions:} artifact persisted; traceability updated.

\subsection{UC-04, Configure Reminders}
\textbf{Primary actor:} Estimation Manager. \textbf{Preconditions:} target exists. \textbf{Main flow:} (1)~user creates reminder; (2)~system persists reminder parameters; (3)~reminder flagged for processing. \textbf{Postconditions:} reminder persisted; outbound dispatch deferred.

\subsection{UC-05, Consult Pipeline Analytics}
\textbf{Primary actor:} Executive. \textbf{Preconditions:} authenticated dashboard access. \textbf{Main flow:} (1)~user requests dashboard; (2)~UI consumes analytical endpoints; (3)~KPIs rendered. \textbf{Alternate flows:} null financial values suppressed. \textbf{Postconditions:} read-only access logged.

\subsection{UC-06, Query Copilot in Portfolio Mode}
\textbf{Primary actor:} any authorised business actor (Estimation Manager, Estimator, or Executive) operating the copilot in portfolio mode. \textbf{Preconditions:} authenticated. \textbf{Main flow:} (1)~user submits turn; (2)~pipeline classifies intent; (3)~ExecutionPlanFactory orchestrates deterministic retrieval, context building, and guardrails; (4)~response delivered. \textbf{Alternate flows:} failure routes to Path~8. \textbf{Postconditions:} turn forensics persisted.

\subsection{UC-07, Query Copilot in RFQ-Bound Mode}
\textbf{Primary actor:} an RFQ-authorised actor (Estimation Manager or Estimator). \textbf{Preconditions:} RFQ selected. \textbf{Main flow:} as UC-06, primarily executing Path~4. \textbf{Postconditions:} evidence anchored to target RFQ.

\subsection{UC-08, Manage Workflow Templates}
\textbf{Primary actor:} Administrator. \textbf{Preconditions:} administrative context. \textbf{Main flow:} (1)~user inspects template metadata. \textbf{Alternate flows:} schema edits deferred to external tooling. \textbf{Postconditions:} catalog consistency maintained.

\section{Path Registry Structure}
\label{app:path-registry}

The Path Registry encodes the entire copilot policy surface as structured configuration. Key vectors include \texttt{intent\_topics}, \texttt{resolver\_strategy}, \texttt{access\_policy}, \texttt{forbidden\_fields}, \texttt{memory\_policy}, and \texttt{active\_guardrails}. The registry currently operationalizes Path 1, Path 4, and the Path 8 exception matrix, validating that new execution capabilities require only declarative configuration updates rather than low-level pipeline refactoring.
